# PR-17：三层预算门禁（栏目、剧集、供应商）

这一步把 **Column → Series → Provider** 三层本地预算预留接入镜头任务账本，默认**拒绝**没有政策的付费提交意图。只供内部 Python 进程调用，不是已启用的云端 Worker、真实供应商账单封顶或公开管理 API。

## 可验证能力

- `budget_policies`：栏目、剧集及供应商独立政策，每次更新插入不可变新版本，记录 `daily_limit_usd`、`max_active_jobs` 和启用状态；始终按最新有效版本判定。
- `job_budget_reservations`：每个已领取任务只能保留一条额度预留；金额使用 `Decimal` 两位小数，记录 UTC 日期、来源栏目/剧集/供应商和冻结的政策版本。
- **先领取、再预留、然后提交意图**：`claim_next_job → reserve_job_budget → record_submission_intent → (未来实际生成)`。缺少任何一层政策、额度不足、并发满或租约过期均拒绝。
- 多个 Series 可以共享同一 Column 的日额度与并发数量；每个 Series 还有自己的上限；不同 Provider 可独立设额度。
- 预留量与带证据的历史实际账单均计入当日预算，避免“前一镜头已经用了钱却被当作空闲额度”。
- 只有当**从未持久化任何生成意图**时，才允许操作者人工释放未提交预留。提交意图之后失败、网络断开或供应商 Task ID 未返回时，预算始终保留，防止冒进。
- `record_operator_verified_charge` 要求人工证据引用与操作者标签，记录实际金额和超预留情况；不从供应商 API 自动查询账单，不能称为官方确认。
- 预留事件使用 SQLite 触发器限制修改/删除，所有操作处于 `BEGIN IMMEDIATE` 原子事务。

## 风险边界

**这是一套本地软件门禁，不是 Google API 的强制账单硬限额。** 实际费用可能超过预留金额，供应商扣款也可能延迟；若正式供应商报价不可验证或响应不明确，仍需人工审核。使用者应在 Google Cloud/AI Studio 配置平台提供的额外预算告警与限流（按当时供应商支持能力）。

当前程序没有对外暴露管理密钥的 HTTP 权限、没有定时 Worker、没有云端自动付费。操作界面也未加入额度编辑，避免在未鉴权服务上提供预算放行入口。

## 验收

测试覆盖缺一层政策就拒绝、两个剧集共享栏目额度、独立供应商限制、每级并发限制、仅未提交时允许释放、提交意图后冻结、手工账单核对、超预留费用延续约束及事件不可篡改。不执行任何第三方生成调用。
