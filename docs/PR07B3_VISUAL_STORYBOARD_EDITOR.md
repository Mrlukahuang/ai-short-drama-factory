# PR-07b3｜逐镜头可视化分镜编辑（本机）

## 新增的实际界面

Streamlit 「分镜与审批」现在优先显示「逐镜头可视化编辑」而不是默认打开 400 行的 JSON。可直接编辑：

- 分集编号、标题、开头钩子、结尾悬念；
- 每镜的长度（1–30s）、动作、摄影方式、起点/终点人物与道具连续性；
- 本剧演员多选、本剧场景选择；
- 对白表格：逐句说话演员、原台词、可选起止整秒。可新增/删除行；未填写时槽的镜头延续旧版平均分配规则；不允许部分填写、重叠、倒序或越过镜头长度。

表单必须按「应用修改到草稿」后才会写入本次 Streamlit 会话的 JSON 草稿，**不会创建 Episode、不会自动批准**。草稿发生变化时旧服务器校验自动失效；之后仍需操作员分别点击：服务器校验 → 检查并人工确认提交 Episode → 创建 Production → 剧本批准 → 人物和场景批准 → 本机免费离线 MP4 生成与技术审片。

「高级 JSON 编辑」继续保留，支持专家直接编辑完整 `screenplay.zh.v1`。修改时不要混淆表单未提交的输入与已应用草稿；一切审核以已应用/已校验版本为准。

## Fail-closed 合同

纯 Python `apply_visual_storyboard` 会拒绝镜头数量/顺序/ID 变化、未知演员与场景、重复演员、对白说话人非本镜头出场者、缺失或不合法对白、半填/越界/重叠时槽、时长超出 90 秒；任何出错不会修改原草稿，任何新增表格行不会被静默丢弃。所有 ID 即使本机语法看似有效，最终仍由现有服务端 `check_screenplay_scope` 判定是否属于当前剧集。

新增 `tests/test_visual_storyboard.py` 覆盖有效结构化修改、服务端真验证、原验证指纹过期、多行定时对白与静音镜头、13 类不合法改动，以及后端-only CI 对 Streamlit 源代码语法的解析检查。

## 边界和成本

本界面是无账户权限的**本机开发工具**，只能绑定 `127.0.0.1`，不允许开放公网。不新增数据库结构、付费模型调用、真实 AI 影视镜头或第三方个人素材上传。纯离线测试成本为 0，原 Google TTS/TxLab 一次性收费工作流仍然硬关闭。

下一步：更丰富的导演时间轴/角色连续性和安全的本地媒体选择；仍需独立权利验证、生产级用户认证、真实媒体模型实测和实际供应商成本证明后才可能商业发行。
