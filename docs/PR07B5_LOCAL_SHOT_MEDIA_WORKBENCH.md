# PR-07b5｜把本机原创视频真正接入审片工作台

## 本次交付

此前已有真实 FFmpeg 媒体适配器 `render_approved_preview(..., source_clips={shot_id: path})`，可以用真实本地视频替换某个技术占位镜头，但 Streamlit 无法操作它。本阶段在「本机审片」里，给**已经人工通过剧本与人物审批的 Production** 增加：

1. 选择这一 Production 的镜头 ID；通过本机文件选择器选择自己的 MP4/MOV/WEBM/MKV（单文件 **32 MiB** 上限）。
2. 亲自勾选「拥有原创权利或明确授权用于本机技术试片」。未经操作员明确勾选，**绝不写入本机素材仓**；此勾选并不证明法律上的授权。
3. 「登记」按钮只复制本机视频、检查 ffprobe 单视频轨/镜头长度、写入内容哈希与绑定收据，不调用任何收费模型，不生成或发布影片。
4. 显示各镜头「已登记本地视频」或「占位」。重新打开 Streamlit 仍可通过本机收据恢复绑定。
5. 「生成 / 更新已审核的离线 MP4」先重新读取**本机逐镜哈希和媒体格式**，再通过现有 `render_approved_preview` 渲染；没有素材的镜头仍使用占位画面。既有多轨字幕、FFmpeg 完整解码、独立 QA 和只读播放器继续工作。

## 存储与安全边界

- 只写入与 API 相同的**本机磁盘**：`DRAMA_FACTORY_DATA_DIR/local-shot-media/<series_id>/<production_id>/`。视频字节按 SHA256 内容寻址，不覆盖已有文件；某镜头显式再次「登记」才会原子更新其绑定收据，其它镜头原样保留。
- 不允许任意路径作为导入参数；浏览器提供的上传名只用于识别扩展名，文件路径由可信项目 ID、生产 ID 和哈希生成。拒绝根目录/分集路径/媒体/绑定收据符号链接、超限大小、错误格式或错误长度、跨剧引用、未通过两个生产审批的上传与读取。
- 每次生成前检查收据和视频字节哈希并重新执行 ffprobe；哪怕有一个已登记镜头损坏，也**整次拒绝**而非悄悄改成占位视频。源文件不包含在 Git 仓库和 Actions Artifact 中；Git 仅保存代码、文档和完全合成的测试材料。
- 表单与后台 API **没有身份登录、病毒扫描、沙盒式媒体解码、加密存储、专业版权审查和公网安全隔离**，严禁对公网开放，更不可上传机密原作、第三方受保护素材、真人脸/声样到此原型。建议专门本地低风险测试环境运行，并在接入可信用户资产之前补齐安全部署。
- 本地权利声明字段只表示 **self_attested**。没有独立商业使用许可证明、肖像授权、真实生成镜头、TTS 或可公开发布的成片。

## 验收与测试

新增 `src/drama_factory/pipeline/local_shot_media.py`、`tests/test_local_shot_media.py`。CI 用 FFmpeg 生成完全合成的原始测试视频，验证真实视频镜头+占位镜头合成出可解码 MP4，记录了 `provided_local_clip` 与原有技术 QA 通过；覆盖持久恢复、同镜替换、其他镜头缓存不受影响、无授权勾选、错误扩展/损坏文件/跨剧或未审批 Production、源内容/收据篡改、符号链接和 Python UI 语法。仍要求 Python 3.11、3.13、native local libSQL、FFmpeg offline-video 四项 CI 全绿。

**不改变数据库 Schema、不添加云端上传接口、不调用任何收费 Provider，本测试总付费模型费用 US$0。**
