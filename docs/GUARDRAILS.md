# 防跑偏规则（GUARDRAILS）

> 给 Claude Code、GPT/Codex 及任何 Agent。违反任何一条的 PR 不合并。

## 1. 开工前必做（每个会话、每个任务）

1. 读 `AMEND.md`（全部 Active 条目）。
2. 读 `docs/handoff/CURRENT.md`，确认**当前阶段**和**下一个任务**。
3. 在动手之前，用一句话写出：「本任务对应 `Stage: Gx / Req: Rx.y`，交付物是 ___」。写不出来就停下问所有者。

## 2. 七条硬规则

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **只做当前阶段的需求。** 下一阶段的东西，哪怕“顺手”，也不做 | 过去的偏离都是“顺手加固” |
| 2 | **不碰冻结路径**（见 AMEND-001）。CI 会拦 | storage 已经 7k 行，零产出 |
| 3 | **一个 PR 只对应一个 Req 编号**，代码改动建议 ≤ 600 行（测试另计） | 小步可审 |
| 4 | **先跑真实模型，再写防护。** 没有真实调用证据的环节，不写恢复/对账/迁移/fencing 代码 | “先验证、后加固” |
| 5 | **不新建抽象层**，除非已有 ≥ 2 个真实实现需要它 | 防止为未来过度设计 |
| 6 | **不发明新的“实验版本号”**（txlab v6、canary v3 之类）。需要实验先写一页提案，所有者批准 | PR31 就是这样膨胀的 |
| 7 | **能借就借。** 动手前先查 `docs/REFERENCE_PROJECTS.md` 有没有现成做法；MIT/Apache 可借鉴代码（保留署名），NC/Elastic 只借思路 | 不重复造轮子 |

## 3. 什么时候必须停下来问所有者

以 **AMEND.md 的 AMEND-004** 为准（自主连续开发模式）。简要：超过 2 USD/次或 5 USD/天的付费调用、需要新授权或密钥、改冻结路径或治理文件、阶段退出需要人工评分签字、同一检查修 2 次仍红、删文件或改表结构。

叫所有者的方式：新建 `[需要所有者]` Issue，然后继续做不依赖它的下一个 Req。

需求理解有歧义时：选最保守、改动最小的解释，在 PR 描述里写明假设，**不要停工等待**。

## 4. 结束时必做

1. 更新 `docs/handoff/CURRENT.md`（做了什么、没做什么、下一步、遇到的问题）。
2. PR 描述按模板填写 `Stage` / `Req` / `AMEND check`。
3. 区分「已实现」「已用真实模型验证」「只是 Fake」——不得混写（沿用 AGENTS.md 第 7 条）。

## 5. 跑偏的典型信号（Agent 自检）

- 我在写的代码，当前阶段的验收标准用不到 → **跑偏**
- 我在给一个还没真实跑过的环节写崩溃恢复 → **跑偏**
- 我在新建 `*_v2`、`*_lab`、`*_canary`、`*_rehearsal` 文件 → **大概率跑偏**
- 文档比代码长、测试比功能多 3 倍以上 → **警惕**
- 这周没有任何一个产出物是人能看/能听的 → **跑偏**

## 6. 双 Agent 协作（Claude Code ⇄ GPT）

- 同一时间只有一个 Agent 在一个分支上工作。
- 交接只通过 `docs/handoff/CURRENT.md` + PR 描述，不依赖聊天记录。
- 接手方先读 CURRENT.md，再跑 `pytest -q` 确认基线绿，再开工。
- 不同意上一个 Agent 的做法：写在 CURRENT.md 的「异议」栏，由所有者裁决，不要直接推翻重写。

## 7. 合并规则

- **全部检查为绿 + PR 模板已填写**：Agent 可以自己合并（AMEND-004）。
- **任何检查为红**：不得合并，也不得建议所有者合并。
- 改冻结路径或治理文件的 PR：CI 会要求 `amend-approved` 标签，只有所有者能加，**Agent 不得自己合并**。
- Agent 不得直接推送到 `main`，一律走分支 + PR。
