# PR-15d — 逐句已批准时槽的多角色字幕与技术 QA

PR-10c/10d 已把经过人工审核的角色、每句台词顺序、起止整秒与 Fake PCM 音轨连在一起，但原字幕仍按**每镜整段台词**显示，因此音轨的停顿会被整镜的字幕掩盖。此次修复视频技术交付中的这个错位。

**渲染：** 对有结构化 `dialogue_cues` 的镜头，每行对应 SRT 独立条目；若有导演批准 `start_second/end_second` 则使用准确时间，若未填则使用 PR-10c 的确定性均匀安排；旧手工镜头仍保留单镜头的技术占位字幕，不臆造说话人。各镜头累积时长将相对时点转换为剧集绝对 SRT 时点。导演明确保留的空档不显示此前的台词，演员 ID 与文本只存在本地生成的 SRT 中，不发送到云端。

**技术校验：** 生成 manifest 中仅登记 `subtitle_schedule`（每句开始秒、结束秒、规范化文本 SHA256，不放原对白）。PR-14 QA 独立重新读取本地 SRT，校验每句序号、起止秒、非重叠、有意留空秒数、最大剧集时长以及文本哈希，拒绝被篡改的 SRT 或时间表。允许字幕出现经审核的停顿（不同于早期要求每镜无空隙的旧版 QA）；没有新 schedule 的历史 Manifest 保留原 QA 检查。

**真正的媒体验收：** GitHub FFmpeg 专项用 6 秒双角色多句剧本真实渲染字幕与 MP4，再对本地 SRT 和 schedule 做修改/错位故障注入。60 秒技术样片要求字幕起止段 `1–10`、`11–19`、`22–39`、`40–60` 秒；最后一个字幕是无台词镜头的**技术提示**，不是演员对白。CI 同时验证既有 60 秒 PCM 静音、音视频 SHA256 和 AAC/H.264/mov_text 轨道。

**残余范围：** MP4 内嵌 mov_text 字幕轨来自同一 SRT，但本次不声称已经跨播放器验证字幕的字体和排版，也不认为这种技术时间轴是自然语言语速、字级对齐或口型同步。字幕文本哈希不是有数字签名的版权凭证。真实 TTS/真人声音、商业授权和正式发布仍保持关闭。
