# 项目章程（Charter）— AI 短剧自动化工厂

> 一页说清楚：做什么、不做什么、怎样算成功。任何 PR 若无法对应到本页的目标，就是跑偏。

## 1. 一句话目标

**用 AI 模型稳定生产「真人风格男女主、中文对白、9:16 竖屏」的短剧成片，每集 60–90 秒，且合格镜头成本可控。**

## 2. 核心用户与场景

- 用户：仓库所有者本人（单人运营的短剧工作室），后期可能扩展到小团队。
- 场景：输入原创故事梗概（或已授权小说）→ 得到可发布的整集 MP4。
- 人只在关键节点审核：剧本、演员定妆、镜头选片、成片。

## 3. 北极星指标（每个阶段都要回到这三个数）

| 指标 | 定义 | G4 目标 |
|---|---|---|
| **合格镜头率** | 人工评审「可用」的镜头 ÷ 生成的镜头 | ≥ 50% |
| **每合格分钟成本** | 实际 API 账单 ÷ 合格成片分钟数 | ≤ 30 USD/分钟（G1 后修正） |
| **单集人工时长** | 从梗概到成片的人工操作时间 | ≤ 2 小时/集 |

## 4. 范围（In Scope，按优先级）

1. 原创故事 → Story Bible → 分集剧本 → 分镜（LLM 生成 + 人审）
2. 固定演员资产：多角度定妆图、服装版本、固定音色
3. 逐镜头视频生成（多 Provider 可切换），失败只重试单镜头
4. 对白：模型原生音频 **或** TTS + 口型同步（G1 决定）
5. 字幕、配乐、FFmpeg 合成、技术 QA
6. 预算门禁与费用记录
7. （G6 之后）授权小说 → 事件图 → 季规划 → 接入同一剧本 Schema

## 5. 非目标（Out of Scope，直到所有者在 AMEND.md 中解除）

- ❌ 云端多人平台、权限系统、公网部署
- ❌ Turso / libSQL / 分布式事务 / 多进程 fencing 实验
- ❌ 自研 3D 导演编辑器、Godot 集成
- ❌ 2D 漫剧、3D 动画风格（数据结构兼容即可，不做专门功能）
- ❌ 自建模型训练、微调
- ❌ 为“未来可能需要”而写的抽象层

## 6. 成功的定义

**第一个里程碑成功 = 一集 60 秒、2 个固定主角、中文对白、真实 AI 视频的 MP4**，人工评审愿意发布，账单可查。在这之前，其它一切都是次要的。

## 7. 技术原则（保留自 ADR-001~008）

- Python 是唯一总控；LLM / Skills 只产内容，不能绕过审核、版权、预算门禁。
- Provider 必须可替换，并有 Fake 实现和不需要密钥的契约测试。
- 资产只追加不覆盖；镜头级幂等，不允许整集盲目重跑。
- 小说原文、模型输出都是不可信数据。
- **新增原则：先验证、后加固。** 某环节没跑通真实模型之前，不为它写恢复/对账/迁移代码。
