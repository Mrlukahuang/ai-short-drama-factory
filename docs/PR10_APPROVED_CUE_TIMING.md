# PR-10d｜审核台词精确起止秒数与实际静音间隔（离线）

此前 PR-10c 能把多演员多句台词拼成一条 PCM 音轨，但为每句**平均分配镜头时长**，无法表达导演批准的对白延迟、停顿和无声反应。此次给 `Screenplay.DialogueCue` 和审核后的 `ShotDraft.dialogue_cues` 加入可选 `start_second` / `end_second` 整秒时间段。

**审批约束：** 每行必须同时填写开始/结束或全部省略；时间必须整数、非负、结束大于开始、按原批准句序递增、不重叠、不超过镜头总时长。同一镜头不得有的台词填写、有的未填写。对未经审核或后续篡改的存储 EpisodeDraft，同样执行结构化校验。此前不带时间字段的旧剧本继续按平均分配，**绝不自动补充一个伪造的“导演审批时间”**。

**合成机制：** 多演员 FakeProvider 根据**批准的**每句时长生成非语言正弦测试音，用真实 48kHz PCM 零值帧铺出第一句前、两句之间、尾句之后及无声镜头的静音。主时间线 SHA256 key 包括逐句 `start_second` 和 `end_second`，移动台词位置后不会误复用旧整体音轨；如果没改变单句声音内容，逐句缓存仍可以复用。绝不推断自然语言语速、口型或角色声音。

**免费 CI 真验收：** 两个虚构演员的 60 秒样片，第一镜头台词时间从第 1 秒开始、在第 10-11 秒有停顿；第二镜头直到整个视频第 22 秒才开始，最后第 40–60 秒无声。CI 在 FFmpeg 编码后从实际 PCM WAV 分段读取，逐字节验证静音段的 `0x00` 数据，同时检查有声区非零、整轨帧数、混音 MP4 的输入 SHA256、视频 AAC/H264/字幕和 QA、零付费 Provider。专门单元测试还覆盖逆序、越界、重叠、半填字段、错误类型及旧脚本兼容。

**残余缺口：** 目前为整秒技术计划，真实 TTS 的毫秒/字级对齐、多角色重叠对话、真正发音时长、声线独立授权与 lip-sync 仍未验收。不可声称 AI 视频或实际配音已生成，更不能自动发布。
